# /analyze hot-path flamegraph — 2026-05-16

A py-spy flamegraph of the ``POST /analyze`` request would live next to
this file as ``2026-05-16.svg``.

## Status: not produced in this PR

The PR-builder backend container (``fed-pulse-backend:latest``) does not
carry ``py-spy`` in ``requirements.txt`` / ``pyproject.toml`` and the
isolated PR build is not permitted to install new system packages or
fetch unpinned dev tools from PyPI. Adding py-spy to the runtime image
just to attach a profiler is the wrong tradeoff at this stage; the
backend container should stay minimal.

## How to produce the artefact locally

The intended workflow, kept here as a recipe so the next reviewer can
reproduce it in ten minutes:

```sh
# In a dev environment with py-spy installed on the host (not inside the
# minimal backend image):
pip install py-spy

# Start the dev backend the usual way.
make dev-cpu

# Identify the uvicorn worker PID.
docker compose ps backend
docker compose top backend | awk '/uvicorn/ {print $2; exit}'

# Run a single /analyze request in a second terminal.
curl -s -X POST http://localhost:8000/analyze \
  -H 'content-type: application/json' \
  -d '{"text":"FOMC raised the target range by 25 basis points...","date":"2024-09-18","symbol":"^GSPC","forecast_mode":"fast","horizon":"3d","include_realized":false}' \
  > /dev/null &

# Sample for 30 seconds and emit the SVG.
sudo py-spy record -d 30 -p <PID> --format flamegraph -o docs/perf/2026-05-16.svg
```

The expected hot bands are: the sentiment classifier forward pass (most
of the wall-clock on cold start), market-data fetch (when ``live`` source
is configured), and the forecaster's one-shot inference loop. Re-run the
profile whenever the inference path is restructured.
